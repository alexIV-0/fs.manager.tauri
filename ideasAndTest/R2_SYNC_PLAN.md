## 1. Одна фраза

> **Решения о хранилище — на бэкенде. Байты — у меня.**
> Бэкенд говорит «можно, вот подписанная ссылка», а везёт файл моя программа: сервер физически не
> может залить файл, которого у него нет.

Это не компромисс, а стандартная схема, и API коллеги на ней и построено:
«Bytes go directly to/from R2, **not through the API**».

## 2. Разделение ответственности

| | Бэкенд (`innovation-hub`) | Локальный клиент (эта программа) |
|---|---|---|
| Каталог: что существует, где, что изменилось | **да** (Postgres `project_files`) | копия для скорости |
| Журнал изменений, курсоры | **да** (`storage_changes`) | хранит свой курсор |
| Права, кто что может | **да** | не реализует ничего |
| Ключи R2, подписи | **да** | не имеет ключей вообще |
| Раскладка ключей в бакете | **да** | не выбирает |
| Реиндекс, сверка с бакетом | **да** (`/reindex`) | зовёт при нужде |
| **Передача байтов** | **нет** | **да, напрямую в R2** |
| Что лежит на диске, кэш, вытеснение | нет | **да** |
| Локальная рабочая папка, копии вне зеркала | нет | нет — это другая подсистема программы |
| Состояния файлов, значки, UI | нет | **да** |

**Терминология** (чтобы не путаться в разговоре с коллегой): его часть — **бэкенд хранилища**,
моя — **локальный клиент**. Слово «синхронизатор» означает разное для каждого и порождает споры
на пустом месте.

## 3. Две зоны, а не три

Клиент хранилища отвечает **за одну папку** — зеркало. Всё остальное его не касается.

| Зона | Что | Кто следит |
|---|---|---|
| **remote** | R2 через бэкенд | бэкенд |
| **mirror** | зеркало логической структуры, TTL 4 часа | **клиент хранилища** |
| локальная рабочая папка | `localFolder` → `mainWorkFolder`: сюда нода копирует файлы, тут работают ffmpeg / AE / Moho | **уже существующая часть программы**, там своё автоудаление |

> **Ревизия:** раньше в плане была третья зона «scratch» с собственным TTL и CoW-клонированием.
> Это была ошибка: локальная рабочая папка существует в программе давно (`localFolder` в
> настройках), ею занимается другая подсистема, и клиенту хранилища за ней следить не надо.
> Убрано.

Изначальный мотив третьей зоны — «не дать ffmpeg писать в синхронизируемую папку, чтобы не залить
недописанный файл» — закрыт другим решением: **триггер заливки это явный вызов**, а не слежка за
файловой системой. Значит недописанный файл никто и не увидит.

**Путь файла:** в каталоге виден слепок → нода копирования обращается к зеркальному пути →
`ensureLocal` качает → нода копирует в рабочую папку → обработка → результат кладётся в зеркальную
папку → автозаливка → через 4 часа зеркальная копия вытесняется.

## 4. Контракт с бэкендом

Все запросы: `Authorization: Bearer mch_…`. Токен — **непривязанный** к проекту
(`machine_tokens.project_id = NULL`), иначе не пустит даже админа: `scopedProjectId` проверяется
до роли.

| Эндпоинт | Используем для |
|---|---|
| `GET /api/storage/v1/tree?projectId=&prefix=` | bootstrap индекса, `{ entries, cursor }` |
| `GET /api/storage/v1/delta?projectId=&since=` | догон, до 5000 событий, `truncated` → заново `/tree` |
| `POST /api/storage/v1/presign` | подписанная ссылка PUT/GET, TTL 60–86400 (деф. 3600) |
| `POST /api/storage/v1/notify` | **обязательно** после PUT, иначе бэкенд про файл не узнает |
| `POST /api/storage/v1/mkdir` | создать папку (строка в Postgres, объекта в R2 нет) |
| `DELETE /api/storage/v1/object` | удалить файл/папку каскадом |
| `POST /api/storage/v1/reindex` | сверка с бакетом, owner-only, до 120 с |
| `GET/PUT /api/storage/v1/sidecars` | `folderState.json`, `options.json`, `kind: raw` с `ifMatch` |

**Раскладка ключей** (не наша забота, но знать надо):

```
{AWS_S3_PREFIX}/projects/{projectId}/project-meta.json
{AWS_S3_PREFIX}/projects/{projectId}/options/folderState.json
{AWS_S3_PREFIX}/projects/{projectId}/{folderPath}/{uuid}-{safeName}
```

> **`s3Key` непрозрачный.** Логическое имя (`name`) и путь (`folderPath`) живут в Postgres отдельно
> от ключа. **Локальный путь строим из логического пути, не из ключа** — иначе на диске появятся
> папки вида `a3f9c1-clip.mov`.

**Политика загрузки** (`lib/project-upload-policy.ts`) — не блокер: `video/quicktime` разрешён
(ProRes и HAP пройдут, политика смотрит MIME, не кодек), `application/octet-stream` — универсальная
лазейка. Где тип известен — присылать точный, чтобы сайт понимал, что можно проиграть.

### Capability-флаги — приходят с бэкенда

Хардкодить не нужно: **эндпоинт есть.**

```
GET /api/storage/v1/capabilities
→ { "apiVersion": 1, "multipart": false, "rename": true, "copy": false,
    "sharing": false, "clients": true, "originMtime": true, "contentHash": true }
```

Клиент читает их при подключении и по ним гасит недоступные пункты интерфейса. **Нигде в коде не
должно быть предположения «оно есть»** — только проверка флага.

Состояние на 2026-08-07: `rename`, `clients`, `originMtime`, `contentHash` — **есть**;
`multipart`, `copy`, `sharing` — нет.

## 5. Локальный индекс — схема

SQLite в app data (**не** внутри синхронизируемой папки).

```sql
PRAGMA journal_mode = WAL;

-- Копия каталога. Производное, можно снести и пересобрать через /tree.
CREATE TABLE remote_entries (
    file_id      TEXT PRIMARY KEY,   -- UUID бэкенда: СТАБИЛЕН через переименования и переносы
    project_id   TEXT NOT NULL,
    folder_path  TEXT NOT NULL,      -- 'IN', '' = корень проекта
    name         TEXT NOT NULL,      -- логическое имя
    is_folder    INTEGER NOT NULL,
    s3_key       TEXT,               -- NULL у папок; непрозрачный у файлов
    size_bytes   INTEGER,
    content_type TEXT,
    etag         TEXT,
    content_hash TEXT,
    origin_mtime INTEGER,
    last_seq     INTEGER,
    deleted      INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX idx_re_folder ON remote_entries(project_id, folder_path, name);
CREATE INDEX idx_re_name   ON remote_entries(name);

-- ТОЛЬКО эта машина. Никуда не уходит.
CREATE TABLE local_state (
    file_id      TEXT PRIMARY KEY,
    state        TEXT NOT NULL,     -- Cloud|Downloading|Fresh|Stale|LocalOnly
                                   -- |LocalModified|Uploading|Conflict|Error
    local_path   TEXT,
    -- ВАЖНО: local_size и local_mtime — состояние на момент ПОСЛЕДНЕЙ УСПЕШНОЙ
    -- синхронизации (гидрации или заливки), а НЕ текущее с диска. Текущее берётся
    -- stat-ом и сравнивается с ними — это и есть baseline для детекта локальной правки.
    local_size   INTEGER,
    local_mtime  INTEGER,
    synced_etag  TEXT,
    hydrated_at  INTEGER,
    last_access  INTEGER,
    pinned       INTEGER NOT NULL DEFAULT 0,
    error        TEXT
);
CREATE INDEX idx_ls_evict ON local_state(last_access) WHERE pinned = 0 AND state = 'Fresh';

-- Очередь передач: переживает перезапуск.
CREATE TABLE transfers (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    file_id      TEXT,
    project_id   TEXT NOT NULL,
    direction    TEXT NOT NULL,     -- 'up' | 'down'
    local_path   TEXT NOT NULL,
    bytes_total  INTEGER,
    bytes_done   INTEGER NOT NULL DEFAULT 0,
    strategy     TEXT NOT NULL,     -- 'single' | 'multipart'
    upload_id    TEXT,              -- ← для multipart, пока NULL
    parts_done   TEXT,              -- ← JSON [[partNumber, etag]], пока NULL
    attempts     INTEGER NOT NULL DEFAULT 0,
    state        TEXT NOT NULL,     -- queued|active|paused|error|done
    error        TEXT,
    updated_at   INTEGER NOT NULL
);

-- Курсор НА ПРОЕКТ (не глобальный: /delta требует projectId).
CREATE TABLE project_cursors (
    project_id TEXT PRIMARY KEY,
    cursor     INTEGER NOT NULL,
    tree_at    INTEGER
);

-- Что и куда копировали: чтобы нода «переписать устаревший» решала БЕЗ скачивания.
CREATE TABLE copied_files (
    dest_path  TEXT PRIMARY KEY,   -- куда скопировали (вне зеркала)
    file_id    TEXT NOT NULL,      -- из какого файла
    src_etag   TEXT,
    src_hash   TEXT,
    src_size   INTEGER,
    copied_at  INTEGER NOT NULL
);

-- Медиа-характеристики облачных файлов. Заполняется ЛЕНИВО, без скачивания.
CREATE TABLE media_probe (
    file_id   TEXT PRIMARY KEY,
    src_etag  TEXT NOT NULL,       -- инвалидация: etag изменился → проба протухла
    duration  REAL,
    width     INTEGER,
    height    INTEGER,
    codec     TEXT,
    fps       REAL,
    audio     TEXT,
    probed_at INTEGER NOT NULL
);

CREATE TABLE sync_meta (k TEXT PRIMARY KEY, v TEXT);
```

### Метаданные и превью без скачивания

В каталоге бэкенда **нет медиа-характеристик** — он знает файл как объект (размер, тип, `etag`), но
не знает, что внутри. Длительность, разрешение, кодек добываются пробой:

> **`ffprobe` читает по HTTP через Range-запросы** — вытягивает только заголовок контейнера (moov).
> Сотни килобайт вместо гигабайт, ~секунда. Для облачного мастера на 5 ГБ показываем
> «1920×1080, 00:02:34, h264, 25 fps», ничего не качая.

- Кэш — `media_probe`, инвалидация **по `etag`**.
- Заполнять **лениво**: навёл на файл / открыл «Информацию». Не при обходе дерева.
- `+faststart` ускоряет пробу (moov в начале = один короткий Range).
- **Зависимость:** Range-запросы по presigned GET — отдельный пункт проверки в шаге 0.

**Превью картинок:** presigned GET URL отдаётся прямо в `<img src>`, файл на диск не сохраняется. Это
заодно обходит боль WKWebView с `file://`. **Грабля:** для чтения пикселей через canvas
(`getImageData`, `canvasFilters.ts`) нужен `crossOrigin="anonymous"`, а он требует настроенного CORS
на бакете — это настройка владельца бэкенда.

**Превью видео-кадра — отложено осознанно**, обсудим отдельно.

**Ключевое свойство:** `file_id` не меняется при переименовании и переносе. Значит дельта с новым
`name`/`folder_path` у известного `file_id` = **локальное переименование файла в зеркале, без
перекачивания**.

### 6.1. Шов гидрации — главное место всей работы

Объект на обработку собирается **до** того, как файл появится на диске: в каталоге виден слепок,
построен локальный путь, путь положен в объект. **Путь есть, файла нет.** Файл появляется, когда
нода копирования его открывает.

Отсюда неочевидное следствие:

> **Любая проверка `exists()` / `stat()` по зеркальному пути вернёт «файла нет».**
> Если где-то есть «файл существует? нет — пропускаем», негидратированный файл будет молча
> выпадать из обработки.

Значит шов — это не только чтение:

| Что | Почему |
|---|---|
| `exists`, `stat`, размер | иначе пропуск элемента или «0 байт» |
| чтение / открытие | очевидно |
| **нода копирования** | **основной путь, 99% случаев** |
| передача пути внешней программе (AE, ffmpeg, Moho) | они откроют сами, наш код этого не увидит |

### Шов оказался ТРЁХ видов, а не одного

Это выяснилось при реализации и в исходном плане отсутствовало. Одинаково гидратировать всё — ошибка:

| Что нужно коду | Что делать | Где |
|---|---|---|
| **байты** | гидратировать | `read`, `copy`, `hash`, ffmpeg, AE |
| **метаданные** | ответить **из каталога**, НЕ качать | `stat`, `info`, `getFileInfo` |
| **существует ли** | ответить **из каталога**, НЕ качать | `exists`, `pathExists` |

> **Ловушка, которая стоила бы всего архива.** `findFilesForSingleFolder` зовёт `getFileInfo` на
> **каждый найденный файл**. Если бы `stat` гидратировал, первый же обход проекта скачал бы весь
> архив целиком.

И обратное следствие: **`exists` для облачного файла обязан возвращать `true`**, даже если копии нет.
Файл существует — просто пока не здесь. Иначе проверки вида «нет файла — пропускаем» молча выбросили
бы из обработки всё облачное.

Реализовано командой `storage_path_info`: отвечает про путь (существует / локально / размер / время /
`file_id`) **без единого байта по сети**.

**Форма шва — принимает путь, который у кода уже есть:**

```ts
// было
const data = await readFile(p)
// стало
const data = await readFile(await ensureLocal(p))
```

Внутри путь разворачивается в `file_id` через индекс. **Вне зеркала `ensureLocal` — no-op:** путь в
рабочей папке, абсолютный путь из Custom File, режим `PlainFolder` — всё возвращается как есть,
мгновенно.

Это снимает главный риск шага 5: **не надо решать «здесь надо или не надо», ставим везде**, где путь
превращается в файл.

**Полное дерево решений:**

```
абсолютный нормализованный путь
│
├── НЕ под корнем зеркала  →  как раньше: exists? да / нет. Никакой сети
│
└── под корнем зеркала
    ├── разобрать путь в (projectId, folderPath, name)
    ├── в индексе НЕТ такой записи
    │   ├── файл на диске есть  →  LocalOnly (положили руками) → отдать путь
    │   └── файла нет           →  обычная ошибка «не найдено»
    └── в индексе ЕСТЬ
        ├── локально нет                    →  качаем → отдать путь
        ├── локально есть, версия совпадает →  отдать путь  ← быстрый путь, 0 сети
        └── локально есть, в облаке новее   →  качаем заново → отдать путь
```

Две ветки здесь неочевидны:

1. **«Локально есть, но в облаке новее»** — без неё работаешь со старой версией и не знаешь об этом.
   Проверка бесплатная: актуальный `etag` уже в локальном индексе, запроса в сеть не нужно.
2. **«В зеркале есть, в индексе нет»** — файл положили руками, это `LocalOnly`, его надо **залить**,
   а не гидратировать. Перепутаешь — программа полезет качать то, чего в облаке нет.

**Как надёжно определить «под корнем зеркала».** Наивный `startsWith` ломается:

| Грабля | Что делать |
|---|---|
| **Регистр на macOS** | ФС регистро-нечувствительна, сравнение строк — нет. `/Users/x/Mirror` и `/users/x/mirror` — один путь, но `startsWith` скажет «нет». Сравнивать в нормализованном регистре |
| Относительные пути | сначала привести к абсолютному |
| Хвостовые слэши, `..` | канонизировать до сравнения |

Корень зеркала не настроен (режим `PlainFolder`) → под зеркалом не находится ничего, всегда локальная
ветка. Без ветвлений.

**Свежесть индекса.** Быстрый путь доверяет индексу, а индекс догоняется дельтами при открытом
проекте — если проект закрыт, поллинга нет и индекс отстаёт. Поэтому: **один `/delta` в начале витка
обработки**, дальше весь виток доверяем индексу. Один запрос на проект вместо HEAD на каждый файл —
при десяти тысячах элементов это разница между одним запросом и десятью тысячами.

**Где врезано (сделано):**

| Слой | Точка | Охват |
|---|---|---|
| **Плагины** | обёртка `fs` в `plugins-dev/_template/tauri.ts` | **все 34 плагина, ни один не изменён** |
| Ядро | `src/Utils/storageSeam.ts` + врезки в `findFilesForSingleFolder`, `processItem` | `commands.*` идут мимо шаблона |

Плагинный шов оказался **одним чокпоинтом**: 34 плагина импортируют `fs` из шаблона, поэтому обёртка
там покрыла всех сразу.

**Быстрый гейт — обязателен.** Сканирование локальной папки не должно платить ни одним лишним
IPC-вызовом за облако, которого нет. `storageSeam` один раз спрашивает корень зеркала и кэширует; пока
он пуст, все функции отвечают мгновенно и в Rust не ходят. Кэш сбрасывается при подключении — иначе
шов остался бы выключенным до перезапуска программы.

**Префетч — почти бесплатное улучшение.** `findAllFilesForProcess` строит весь список заранее,
значит известно, какие файлы понадобятся. Пока обрабатывается первый элемент, тихо качаем следующие.
Вместо «каждый элемент ждёт свои три минуты» — «подождал один раз в начале». Новой механики не
нужно: та же очередь передач, задания в неё кладёт раннер.

**Что должно быть видно:** элемент показывает «скачивается 47 %», а не выглядит зависшим; отмена
витка отменяет передачу; два элемента запросили один файл → качаем один раз; не скачалось → элемент
падает с внятным «не удалось получить исходник», а не «файл не найден».

### 6.1.1. Статистика: JSONL остаётся, меняется момент заливки

`db_analytics.rs` **не трогаем.** Он пишет JSONL рядом с проектом
(`{project}/options/__stat/2026.06.jsonl`) плюс агрегаты в `.json` — децентрализованно, данные
путешествуют вместе с проектом. Это правильная конструкция, и к индексу хранилища отношения не имеет:
статистика про проделанную работу, индекс про то, что где лежит.

**Заменять статистику на SQLite нельзя** — и как раз из-за R2: файл базы в объектном хранилище это
та самая отвергнутая ловушка (объекты неизменяемы → каждая новая строка = перезалив всей базы).
JSONL тут строго лучше.

Но одна вещь меняется:

> **В R2 нет дописывания в конец.** Локально `appendRecord` через `O_APPEND` работает как раньше. А
> попадание файла в облако перестаёт быть бесплатным: каждая новая строка означает перезалив всего
> месячного JSONL целиком.

Лечится не переделкой статистики, а **моментом заливки: один раз в конце витка, а не после каждого
элемента.** Раз триггер заливки явный, раннер сам решает когда.

Порядок цифр: строка ≈ 500 байт, 1000 элементов в месяц ≈ 500 КБ. Заливка раз в виток (20 витков) =
20 PUT'ов и ~5 МБ. На каждый элемент = 1000 PUT'ов и ~250 МБ. **В деньгах разницы нет** (доли цента),
батчим ради того, чтобы не гонять четверть гигабайта впустую.

### 6.2. Нода «переписать устаревший» — проверка ДО гидрации

У ноды копирования есть режим «переписать устаревший». Файл копируется в рабочую папку, живёт там
своей жизнью, а зеркальная копия за это время вытесняется. На следующем витке надо понять, нужно ли
качать заново.

**Порядок критичен** — иначе скачаешь 3 ГБ, чтобы выяснить, что качать было не нужно:

```
1. copyState(src, dest)?     ← локальный индекс: 0 запросов, 0 байт
2. UpToDate → не делаем ничего
3. Stale/Missing → ensureLocal(src)   ← только теперь качаем
4. копируем с заменой
5. recordCopy(src, dest)
```

**Сравнивать не время, а версию источника.** Mtime ломается в трёх местах: часы разъезжаются между
машинами, копирование не всегда сохраняет mtime, и если руками правил локальную копию — её mtime
изменился, а источник нет, и сравнение соврёт.

Поэтому таблица `copied_files` помнит, **из какой версии** сделана копия, и сравнение идёт по
`content_hash`, а если его нет — по `etag`. Правило сразу правильное: когда появится multipart,
`etag` перестанет быть хэшем содержимого, а `content_hash` продолжит работать.

```
copyState(srcMirrorPath, destPath) -> UpToDate | Stale | Missing | Unknown
recordCopy(srcMirrorPath, destPath)
```

`Unknown` — dest есть, а записи о нём нет (скопировали руками или до внедрения). По умолчанию
считать устаревшим и перекопировать: безопасно, случай редкий.

Побочная выгода: файл, который не менялся, **не поедет по сети вообще** — заметная экономия на
повторных витках.

### Два инварианта кэша — не настройки

1. **Никогда не вытеснять незалитое** (`LocalOnly`, `LocalModified`, `Uploading`, `Conflict`, `Error` с непрошедшей заливкой) —
   иначе результат рендера исчезнет вместе с локальной копией.
2. **Никогда не вытеснять горячее и запиненное** — `options/*.json` читаются постоянно.

### Состояние считается в ОДНОМ месте

> Один селектор `badgeState`, один `folderAggregate`. Всё, что рисует значки, зовёт только их.

Иначе через месяц три места разойдутся и папка покажет ✓, когда внутри лежит незалитый файл.
Правило приоритета (**ошибка и «не залито» перебивают всё**) живёт внутри селектора.

### Провайдеры и деградация

```
StorageProvider
├── PlainFolder   — локальная папка / сетевой диск. Всё всегда Fresh, значков нет, заливки нет
├── StorageApi    — бэкенд коллеги
└── MockApi       — фикстуры: заготовленные ответы /projects, /tree, /delta, /capabilities
```

**`MockApi` нужен не только на время ожидания доступов.** Он позволяет разрабатывать и проверять всё,
что выше HTTP-слоя, без сети — и остаётся полезным навсегда: тесты, воспроизведение багов, показ
интерфейса без бэкенда. Фикстуры берём из реальных форм ответов (разобраны по коду роутов, не
выдуманы).

При ненастроенном хранилище программа ведёт себя **точно как сейчас**, без единого `if` в
прикладном коде.

### 6.3. Три направления расхождения и конфликт

Различить «в облаке новее» и «у меня новее» по двум величинам нельзя — обе дают `local ≠ remote`.
Нужна третья: **что было на момент последней синхронизации** (baseline в `local_state`).

| локально vs baseline | в облаке vs baseline | Вывод |
|---|---|---|
| не менялся | не менялся | `Fresh` — ничего |
| не менялся | **изменился** | `Stale` → **качаем** |
| **изменился** | не менялся | `LocalModified` → **заливаем** |
| **изменился** | **изменился** | **`Conflict`** |

Детект локальной правки дешёвый: `mtime` + `size` против записанных baseline-значений. Хэш считать не
надо (у mtime есть ложноотрицательный случай — изменили файл и восстановили время, но это редкость).

**Конфликт не авторешаем.** Оба автоварианта теряют данные: «победило облако» — стёрли свой
перерендер, «победило локальное» — стёрли чужую правку. Поэтому: помечаем `Conflict`, показываем `⚠`,
ничего не трогаем, а в контекстное меню даём **«Залить мою версию»** и **«Взять из облака»**.

**Но у явной заливки конфликтов не бывает** — иначе логика конфликтов налезет на нормальную работу:

| Путь | Что делаем |
|---|---|
| **Пайплайн положил результат и вызвал заливку** | **заливаем, точка.** Явное действие всегда право |
| Фоновое обнаружение (вотчер/сканирование) нашло изменённый файл | считаем baseline, при конфликте помечаем |

Перерендер в тот же путь идёт по первому пути — то есть самый частый случай «у меня новее» проходит
без всякой арифметики.

> Маски пишутся от корня проекта: `options/*.json`, `IN/*.txt`, `*.aep`

Дефолт правильный, 95 % пользователей поле не трогают.

Чего в настройках **нет**: Account ID, бакет, ключи R2, версионирование, lifecycle — это бэкенд.

## 10. Multipart: заложить сейчас, включить потом

**Проблема:** `/presign` отдаёт **один** PUT-URL. Одиночный `PUT` в S3/R2 ограничен **5 ГиБ** и не
возобновляется: оборвалось на 4 ГБ — начинай сначала. Бэкенд это изменить не может, потому что
байты идут мимо него; нужны multipart-эндпоинты.

Что делаем **сейчас**:

1. **Схема готова** — `transfers.upload_id` и `transfers.parts_done` уже в DDL. Не удалять.
2. **Исполнитель — стратегия, а не одна функция:**
   ```rust
   trait UploadStrategy { async fn run(&self, t: &Transfer) -> Result<ObjectMeta>; }
   struct SinglePut;   // реализуем
   struct Multipart;   // заглушка
   ```
3. **Выбор по размеру:** `size > multipart_threshold` → `Multipart`.
4. **Гейт по `Caps`:** попал в ветку Multipart, а `caps.multipart == false` → **понятный отказ до
   начала передачи**, а не падение на 4 ГБ из 5.
5. В настройках порог и число частей показываем **задисейбленными** с подписью «бэкенд пока не
   поддерживает».

Когда появятся `create` / `presign-part` / `complete` / `abort` — пишем одну реализацию трейта и
снимаем флаг. Больше ничего не трогается.

**Так же с `rename` и `copy`:** пункты меню есть, задисейблены по `Caps`.

### Демо-сервер — почему он оказался ключевым

Изначально шов (шаг 6) планировался **после** проверки на живом бэкенде. Ход, который снял эту
зависимость: локальный HTTP-сервер в мок-режиме (`storage/mock_server.rs`). Он отдаёт ровно столько
байт, сколько объявлено в каталоге, и принимает заливку — поэтому демо проигрывает **весь путь
целиком**: скачивание с прогрессом, заливку с `notify`, вытеснение, отмену.

После этого шов делался с проверкой, а не на веру. Плюс интерфейс можно показать кому угодно, не имея
бэкенда.

Мок остаётся полезным навсегда: тесты, воспроизведение багов, демонстрация.

### Чего ждём, чтобы запустить 0′

**URL развёрнутого бэкенда.** Токен создаём сами (`POST /api/account/machine-tokens`,
`projectId: null`) — окно для него есть в Настройки → Storage.

Оговорка про первый прогон: бакет пока пуст, поэтому round-trip надо делать **сразу с заливкой** —
иначе `/tree` вернёт пустоту и «работает» не отличить от «не работает».

| ❌ | Глобальная `/delta` без `projectId` | когда станет тесно от N поллингов |
| ❌ | Расшаривание | сайтовый сценарий, нас не блокирует |

Полный список с обоснованиями и сигнатурами — [`STORAGE_BACKEND_REQUESTS.md`](./STORAGE_BACKEND_REQUESTS.md).

**Про расшаривание:** его нет — `findProjectForUser` алиас на `findOwnedProject`, таблицы участников
нет, гостя не существует. Нам не мешает: `role === "ADMIN"` пробивает оба guard'а. Но **не
хардкодить «я всегда админ»** — 403 показывать как «нет прав», а не как сетевую ошибку.

## 13. Граблевник

### Контракт бэкенда

1. **`s3Key` непрозрачный** → локальный путь строить из `folder_path` + `name`.
2. **Presign живёт час** → запрашивать в момент старта передачи, не пачкой на всю очередь.
3. **`/notify` обязателен** после PUT, иначе бэкенд про файл не знает.
4. **`/delta` максимум 5000 событий** → крутить в цикле; `truncated` → выбросить индекс и заново `/tree`.
5. **Курсор на проект**, не глобальный.
6. **Одиночный PUT ≤ 5 ГиБ и без докачки** → гейт по `Caps` до начала передачи.
7. **`options` зарезервирован** бэкендом — 403 на `mkdir` и `delete`.
8. **`scopedProjectId` проверяется до роли** → для программы выпускать непривязанный токен.
9. **Ретеншен журнала ~90 дней** → машина, не включавшаяся дольше, получит `truncated`.

### Найдено при реализации

10. **Регистр на macOS — дважды.** Файловая система регистро-нечувствительна, сравнение строк — нет.
    `/Users/x/Mirror` и `/users/x/mirror` один каталог, но `starts_with` скажет «нет», и файл из
    зеркала пойдёт по локальной ветке. Ловится и в Rust (`paths::under_mirror`, сравнение по
    сегментам), и в TS-предфильтре (`storageSeam.maybeMirror`).
11. **Percent-кодирование в путях.** Имена файлов кириллические, HTTP-клиент кодирует их в пути
    (`ролик` → `%D1%80%D0%BE…`). Демо-сервер молча отдавал пустое тело, пока не добавил декодирование.
    **Нашёл тест** — и только после того, как я закрепил в нём конкретный файл вместо «первого из
    HashMap»: тест с недетерминированным выбором был флакающим по построению и скрывал ошибку.
12. **Baseline обязан обнуляться при вытеснении.** Иначе после повторного скачивания сравнение версий
    возьмёт старое значение и решит, что файл «локально изменён» — свежескачанный файл попросит заливки.
13. **`isSourceNewer` ломается об облако.** Старая версия падала на `stat` несуществующего файла и
    возвращала `true` из `catch` → копировала всегда. Обёрнутая в шов, она стала получать
    `origin_mtime` из каталога, а бэкенд его **пока не заполняет** → ноль → «не новее» → пропуск
    копирования. Итог: для путей в зеркале отвечаем консервативно «копировать», а правильный путь —
    `fs.copyFromCloud`, сравнивающий версию.
14. **Прогресс нельзя писать на каждый чанк** — на большом файле это десятки тысяч записей в БД
    вместо полезной работы. Пишем раз в 4 МБ.
15. **Отмена должна проверяться между кусками** и удалять `.part`. Иначе «отмена» означает
    «дождаться конца и сделать вид», а недокачанный огрызок остаётся мусором навсегда.
16. **Скачивать только в `.part` + атомарный rename.** Запись сразу в целевой файл оставляет при
    обрыве обрезок, который по всем признакам выглядит целым.
17. **Пустая маска «горячих» отключила бы вытеснение целиком** — человек нажал «добавить» и не
    заполнил. Пустые строки отбрасываются.

### Найдено при первом запуске у человека

25. **Команды были только в `collect_commands!`, но не в `generate_handler!`** — и весь клиент
    хранилища (26 команд) не существовал в рантайме. Specta-билдер в `tauri::Builder` **не
    монтируется**: он генерирует `bindings.ts` и всё. Команда, попавшая только туда, компилируется,
    типизируется, проходит все Rust-тесты — и на вызов из интерфейса отвечает «command not found».
    Снаружи выглядит как «кнопка не работает». Ловится теперь тестом
    `специта_и_рантайм_знают_одни_и_те_же_команды` (сравнивает оба списка текстом; компилятор такое
    не видит в принципе). **При добавлении команды правь ОБА списка.**
26. **Ошибка подключения не показывалась нигде.** В секции она была отрисована внутри ветки
    `status.connected`, то есть появлялась только при успешном подключении; в настройках показывался
    лишь `status.lastError`, а исключение самой команды (`error` в сторе) — нет. Провал выглядел как
    полное бездействие, и настоящая причина (пункт 25) не была видна вообще. Ошибку показываем **до**
    и независимо от факта подключения.
27. **`configured` ≠ `connected`.** Пока их не различали, облачная секция висела в первой колонке у
    всех, включая тех, кто адрес и токен не заводил. Секция появляется, только если хранилище
    настроено или уже подключено; настройка и демо живут в Настройки → Хранилище.

### Найдено при запуске интерфейса

Тесты и `tsc` про вёрстку не знают ничего. Всё ниже прошло и типизацию, и 123 теста — и всё ниже
было сломано. Проверялось на стенде: настоящие компоненты и стор, подменённый IPC, headless-Chrome
по CDP (см. `scratchpad/harness`).

18. **Сырой NUL-байт в исходнике.** `dirKey()` склеивал ключ кэша через `\0` — байтом, а не escape'ом.
    Байт невидим в редакторе, не находится `grep`'ом и не виден в diff'е. Колонка содержимого строила
    тот же ключ своим шаблоном через **пробел** → `dirs[key]` не находил ничего, и содержимое проекта
    не показывалось **вообще**. Лечение двойное: escape `\0` вместо байта и **единственная** функция
    `dirKey` на всех (ключ, собираемый в двух местах, разъедется снова).
19. **`flex: 1` без `minWidth: 0`.** Flex-элемент не сжимается ниже min-content, а min-content задаёт
    самое длинное имя файла. Колонка распиралась, родитель с `overflow: hidden` срезал размер и значок,
    а многоточие не срабатывало — «места хватает». Нужен и на колонке, и на самой `Typography noWrap`.
20. **Значок с процентами шире голого** (40px против 15) — колонка размеров дёргалась влево на 26px,
    как только файл начинал качаться. Резервируем фиксированную ширину под значок: числа в списке
    обязаны стоять столбиком.
21. **Секция «Онлайн» росла без потолка** и при 25 клиентах забирала 534 из 684 пикселей колонки,
    сжимая локальные папки до полосы. `maxHeight: 50%` — потолок, а не размер.
22. **`Runtime.enable` в CDP переигрывает историю консоли** текущего контекста. Из-за этого прогон
    показал ошибки **предыдущего** прогона, и правки выглядели неработающими. Сбрасывать
    `Runtime.discardConsoleEntries` после каждой навигации — иначе выводы ложные.
23. **Заголовок в заголовке.** `DialogTitle` — это `h2`, а `Typography variant='subtitle2'` внутри —
    `h6`. Невалидный HTML и ошибка React на каждое открытие модалки; лечится `component='div'`.
24. **Tooltip на disabled-кнопке не показывается** (disabled-элемент не отдаёт событий) — нужна
    обёртка `span`. Касается кнопки «демо», которая disabled ровно в момент подключения.

## 14. Что умерло в ревизии

Чтобы никто не предложил заново:

| Умерло | Почему |
|---|---|
| Маркеры `.keep`, slash-маркеры, `role`/`owner` в маркере | папки логические, живут в Postgres; `mkdir` не создаёт объект в R2 |
| `display_name` отдельно от `prefix` | бэкенд уже разводит логический путь и физический ключ |
| `project_id` = nanoid, `user_id` в префиксе | идентичность — UUID бэкенда; в пути юзера нет |
| Схема ключей «вариант А против Б» | раскладку выбирает бэкенд |
| D1, Cloudflare Queue, consumer Worker | это Postgres, и это не моя часть |
| Свой обход `ListObjectsV2`, снимок индекса в R2 | есть `/tree` и `/delta` |
| Ключи R2 в keychain | machine token |
| Версионирование, lifecycle, abort incomplete multipart | настройки бакета — владелец бэкенда |
| Перенос папок как job с прогрессом, `moving`, окно 404, лимит `CopyObject` 5 ГБ | rename = один `UPDATE`, байты не двигаются |
| `last_known_prefix` для починки | `file_id` стабилен |
| Вся модель прав на моей стороне | enforcement на бэкенде; программа зовёт API и показывает 403 |
| Экран «проекты, потерявшие связь» | терять нечего: идентичность в Postgres |
| Веб-прокси `_web/*.mp4` и постеры | мастера и так MP4 → достаточно `-movflags +faststart` при генерации; кадр извлекается на месте по presigned GET за сотни килобайт |

## 15. Решённое (лог)

| Решение | Кратко |
|---|---|
| Ядро на Rust, **не плагин** | шов `ensureLocal` проходит через каждое чтение файла; плагин не перехватит то, что зовут все остальные |
| Облако = один из провайдеров | `PlainFolder` = деградация до сегодняшнего поведения без ветвлений |
| Триггер заливки — **явный вызов** | `notify`-вотчер только страховка для ручного перетаскивания; поэтому нет проблемы недописанного файла |
| **Зон две, а не три** | локальная рабочая папка (`localFolder`) существует давно и управляется другой подсистемой; клиенту хранилища за ней следить не надо. CoW-клон и «TTL scratch» убраны |
| Проверка «устарел ли» — **до** гидрации, по хэшу | иначе качаем 3 ГБ, чтобы выяснить, что качать не надо |
| Кэш = TTL + лимит + **два инварианта** | остальное не настройки |
| Состояние — **один селектор** | иначе агрегаты разъезжаются |
| Multipart заложить, выключить | стратегия + `Caps`, схема `transfers` уже готова |
| `+faststart` вместо прокси-файлов | не плодить файлы; браузер играет мастер, если moov впереди |

## 16. Открытые вопросы

### Ждут URL бэкенда

1. **Round-trip как сверка контракта.** Заодно ответит на два вопроса, которые пока не проверить:
   отдаёт ли `/tree` пустые логические папки, и работают ли Range-запросы по presigned GET (от них
   зависят характеристики и превью облачных файлов без скачивания).
2. **Максимальный размер мастера.** До ~3 ГБ — можно жить без multipart; от 5 ГиБ это блокер.

### Ждут решения (кода не требуют)

3. **`origin_mtime` на бэкенде.** Колонка есть, `/notify` его теперь принимает — но мы единственные,
   кто присылает. Пока не заполняется у файлов, залитых с сайта, время в интерфейсе будет времем
   регистрации, а не создания.
4. **Где в пайплайне ставить `-movflags +faststart`** для MP4: флаг ноды `convert` или дефолт для всех
   выходов. Без него браузер не начнёт играть файл, не скачав его целиком.

### Отложено осознанно

5. **Превью видео-кадра** — механика та же (ffprobe/ffmpeg по Range), решать будем отдельно.
   См. память `project_cloud_media_probe`.
6. **Тумбнейлы для файлового менеджера** — извлекать кадр на лету и кэшировать локально, или хранить
   постеры. Сайту кадр извлечь нечем (у Worker'а нет ffmpeg), но это решается задним числом.
7. **Multipart на нашей стороне** — стратегия и поля в `transfers` заложены, реализация ждёт
   эндпоинтов бэкенда.
