# Локальный редактор реплик: план

**Статус:** ⬜ не начато. **Очередь: после сайта.** Решение владельца 2026-08-24 — сперва
рабочая версия на сайте, её документ доводится до уровня реализации, эта версия пишется по нему.
Поведение (что именно происходит при drag, прилипании, undo, синхронизации плеера) описано один
раз — в `innovation-hub/docs/TOOLS_SRT_EDITOR_PLAN.md` §13–§21; здесь только наша специфика.
Расхождение в поведении между двумя реализациями — баг, а не вкусовщина.

> Зачем: материал — один аудиофайл с несколькими персонажами. Обработка режет его на дорожки
> по персонажам, из каждой делает текст с таймингами и переводит. Дальше нужен человек:
> вычитать, поправить тайминги, перенести реплики, которые автоматика приписала не тому
> персонажу. Это рабочее место для такой правки — **полностью локальное**.
>
> **Почему у нас, если то же самое делает сайт.** Сайт (`innovation-hub`, раздел «Инструменты»)
> работает только с онлайн-папкой проекта в R2. Под NDA этого нельзя: материал не должен
> покидать сеть клиента. Тогда всё делается программой в локальных папках (в том числе по
> локальной сети), и редактор нужен здесь же — где файловый доступ уже есть и не зависит от
> браузера.
>
> **Что общего с сайтом.** Только **формат документа**: [`DIALOG_FORMAT_CONTRACT.md`](./DIALOG_FORMAT_CONTRACT.md)
> (канонический текст — `innovation-hub/docs/DIALOG_FORMAT.md`). Кода UI общего нет и не будет —
> стеки разные, как и с описанием проекта ([`+PROJECT_DESCRIPTION_EDITOR_PLAN.md`](./+PROJECT_DESCRIPTION_EDITOR_PLAN.md)).
>
> План сайта: `innovation-hub/docs/TOOLS_SRT_EDITOR_PLAN.md` — там же спека двух нод графа
> (§V.4–V.5), которые готовят папку задачи. Ноды нужны обеим сторонам.

---

## 1. Границы

**Делает:** открывает папку задачи, показывает видео, дорожки персонажей с волной и репликами,
даёт править текст, переводы и тайминги, переносить реплики между дорожками, пишет документ и
экспортирует SRT / VTT.

**Не делает:** не озвучивает (следующий инструмент), не переводит (перевод приходит от графа),
не рендерит видео, не ходит в сеть вообще. Ни `storage/*`, ни `ensureLocal`, ни сайта — по
определению NDA-контура.

## 2. Где разрез: окно в ядре, логика в системном плагине

«Плагин со своим интерфейсом и своим бэкендом, которому передают только пути» — почти
реализуемо, но линия разреза проходит не там, где кажется. Проверено по коду:

**Что плагин уже может** ✅

- быть не нодой: `type: ["system"]` существует и работает — `updater`, `remoteWorker`
  (без `ui.json` вообще);
- загружаться из любого окна: `loadPlugin('updater', PLUGIN_VERSION)` вызывается из `MAIN_WIN`
  (`options/plugin/AppUpdaterAccordion.tsx`), а не только из движка обработки;
- получать файловый и прочий доступ: вызывающий передаёт сервисы аргументом —
  `mod.fetchReleases(OWNER, REPO, hostServices.http)`. Отдельное «API для чтения/записи»
  строить не нужно, оно есть: `src/PluginAPI/host.ts` — `fs`, `http`, `ffmpeg`, `exec`, `ae`,
  `paths`, `system`, `fonts`;
- принимать на вход только пути — ровно так и работают все существующие плагины;
- доставляться **отдельно от релиза приложения** (`npm run plug:pack`).

**Чего плагин не может** ⛔

Принести свой интерфейс. UI плагина — это `ui.json`, то есть нода в графе, которую рисует
`NODE_WIN`; механизма «плагин приносит окно или панель с произвольным React» нет, и
contribution points из [`PLUGIN_HOST_API_PLAN.md`](./PLUGIN_HOST_API_PLAN.md) отложены
осознанно. Оба системных плагина это подтверждают: их интерфейс лежит в ядре —
`AppUpdaterAccordion.tsx` у `updater`, обвязка в `AppMain.tsx` и `runner.ts` у `remoteWorker`.

**А можно ли плагину принести своё окно целиком?** Технически — почти можно, и это проверено:
`plugin_protocol.rs` отдаёт по `plugin://` файлы плагина включая `html` (с проверкой путей,
8 тестов), CSP в `tauri.conf.json` не задан, окна создаются программно. То есть плагин может
нести `index.html` со своим бандлом, а программа — открывать его окном.

Почему в плане всё же не так:

- **теряется тема и UI-кит программы.** Инструмент, открытый из программы, должен выглядеть как
  программа; MUI-тема живёт в реалме приложения, в плагинный бандл её пришлось бы затащить
  копией вместе с самим MUI;
- **права окон придётся перекроить.** Сейчас `default.json` даёт `windows: ["*"]` права
  `fs:read-all` и `fs:write-all` — плагинное окно унаследует полный доступ к диску, то есть
  «узкой связки» не выйдет само собой. Сужать default и выдавать широкие права по label —
  правка, которая касается всех четырёх окон;
- **непроверенное место:** доступен ли Tauri IPC со страницы на `plugin://`. Окна, созданные
  Tauri, получают init-скрипт, но у плагинного origin это надо увидеть руками, а не предположить.

Вариант остаётся открытым: если однажды понадобится редактор, который ставится отдельно от
приложения и не обязан выглядеть как оно — это ровно тот путь. Для нынешней задачи он даёт
минус (чужой внешний вид) вместо плюса.

**Отсюда раскладка:**

| часть | где |
|---|---|
| окно, плеер, таймлиния, список реплик, горячие клавиши | **ядро**, `src/DIALOG_WIN/` (§3) |
| чтение / валидация / слияние / запись документа, экспортёры, расчёт пиков, вызов диаризации | **системный плагин** `dialogEditor` (§5.1) |
| ноды графа, которые готовят папку (`diarizeSpeakers`, `dialogDocBuild`, `splitBySpeaker`, `audioPeaks`) | обычные плагины-гейты |

Что это даёт: логику работы с документом можно править и доставлять без релиза приложения, а
она же — самая изменчивая часть (формат будет уточняться по мере работы двух редакторов).
Окно остаётся тонким: рендер и взаимодействие.

Что помнить: плагин исполняется с правами приложения (`ARCHITECTURE.md` §8д, песочницы нет), и
редактор — не то место, где это меняется. Никакого `exec` в логике редактора быть не должно:
только `fs` и `ffmpeg`.

## 3. Где живёт: пятое окно

Сейчас окон четыре (`MAIN_WIN`, `NODE_WIN`, `LOG_WIN`, `PREVIEW_WIN`). Редактор — пятое:
`dialogWin.html` + `mainDialog.tsx` → `src/DIALOG_WIN/`.

Почему окно, а не модалка в главном: это полноценная рабочая поверхность с видео, таймлинией и
списком реплик — человек держит её открытой часами и хочет на втором мониторе. Модалка в
`MAIN_WIN` заняла бы окно файлового менеджера целиком.

**Что помнить про окна** (`CLAUDE.md`): четыре окна = четыре JS-realm'а, zustand между ними не
шарится, межоконная координация — только broadcast-события Tauri. Редактору это почти не
нужно: он общается с файлами, а не с другими окнами. Единственное, что понадобится, —
уведомить главное окно, что документ изменился (обновить значки), и получить из главного окна
команду «открой вот эту папку».

**Точки входа:** контекстное меню папки в главном окне («Открыть в редакторе реплик» —
показывать, если внутри есть `dialog.json` или подходящая раскладка) и кнопка в `NODE_WIN`
после прогона. Механика — как у модалки описания: `useMenuItems.ts` + `ProjectFolderItem.tsx`.

**Геометрия окна** запоминается — в `PREVIEW_WIN` это уже сделано (`preview_bounds.rs`),
брать оттуда подход.

## 5. Что надо написать ⬜

### 5.1. Системный плагин `dialogEditor` — вся логика документа

```jsonc
// plugins-dev/dialogEditor/plugin.json
{
  "id": "dialogEditor", "name": "Dialog Editor Core", "version": "0.1",
  "apiVersion": 1, "type": ["system"],
  "description": "Логика редактора реплик: чтение и запись dialog.json, валидация, слияние, экспорт.",
  "main": "dialogEditor.js", "external": []
}
```

Экспортируемые функции — вход только пути и сервисы, никакого состояния UI:

| функция | что делает |
|---|---|
| `openTask(taskPath, fs)` | читает `dialog.json` (или собирает из раскладки, если его нет), валидирует, возвращает документ |
| `saveTask(taskPath, doc, fs, prev)` | сверяет `mtime`/`size` с `prev`, при расхождении сливает, пишет детерминированно |
| `mergeDocs(mine, theirs)` | слияние по `id` реплики (§8 контракта) |
| `validate(doc)` | порядок проверок §6 контракта |
| `exportProfile(taskPath, doc, profile, fs)` | `srt` / `vtt` / `json` |
| `computePeaks(audioPath, ffmpeg)` | волна через `astats`, обёртка над `parseAstatsEnvelope` |
| `buildFromFolder(taskPath, opts, fs)` | собрать документ для папки без `dialog.json` |

Всё это — чистая логика без DOM: её же (в виде исходника, не бандла) имеет смысл держать одной
копией с сайтом и копировать скриптом со сверкой — приём в проекте уже есть
(`npm run masks:docs` предупреждает о расхождении дублей, `CLAUDE.md` → «Дублированные
источники истины»). Бандл плагина сайту не подходит: там нет ни `plugin://`, ни `hostServices`.

Правило «неизвестные поля сохраняются» (§2.5 контракта) реализуется здесь один раз — и для
окна, и для нод, если они позовут те же функции.

### 5.2. Окно и раскладка

Четыре зоны, как на сайте (тот же скетч владельца): топбар с папкой и состоянием, превью,
список реплик «оригинал ↔ переводы», таймлиния с дорожками. Раскладка резиновая, размеры
запоминаются.

**Что берём из версии сайта, а что пишем сами** — список в
`innovation-hub/docs/TOOLS_SRT_EDITOR_PLAN.md` §20. Коротко: переносится строчка в строчку всё,
что не знает про UI-кит — работа с документом, список операций и undo, экспортёры, координаты и
масштаб таймлинии, отрисовка волны и клипов на canvas, хит-тест и автомат drag, прилипание,
математика виртуализации, синхронизация плеера. Пишется заново — кнопки, панели, поля, модалки,
топбар, сплиттеры, тема: у нас MUI, там Tailwind. Это самая дешёвая часть, и одинаковой она быть
не должна.

### 5.3. Плеер: видео — мастер-часы

`<video>` через `convertFileSrc` — источник времени. Дорожки персонажей — отдельные
`<audio>` / WebAudio, привязанные к `video.currentTime` с коррекцией дрейфа (> 40 мс —
пересинхронизация). Родная звуковая дорожка видео = «общий микс», глушится при включении
персонажных. Mute / solo / громкость на дорожку.

### 5.4. Таймлиния

Canvas на дорожку: волна из `audio.peaks.json`, а если файла нет — считаем `parseAstatsEnvelope`
и кэшируем рядом. Клипы реплик: drag границ (тайминги), drag клипа (сдвиг), drag на другую
дорожку (смена `trackId`), правка текста на клипе, ПКМ-меню (разделить, объединить,
дублировать, удалить, создать пустую реплику). Прилипание к соседям и курсору, `Alt` отключает.
Запреты — из `rules` документа (`minDurationMs`, `overlapWithinTrack`).

Про canvas в WKWebView помнить ограничения из `ARCHITECTURE.md` §4: `ctx.filter` — no-op,
`getImageData` требует `crossOrigin`. Для волны это не мешает — рисуем примитивами.

### 5.5. Список реплик

Слева оригинал, справа колонки языков, обе стороны правятся. Виртуализация обязательна:
реплик бывают тысячи. Подсказки CPS / длины строк по `rules` — мягкие, не блокирующие.
Выделение диапазона, перенос выделенного на дорожку, статус «проверено».

### 5.6. Запись и одновременная правка

Запись — `fs_commands`, перед перезаписью сверка `mtime` + `size` с теми, что были при чтении
(ETag локально нет). Разошлись — слияние по `id` реплики (§8 контракта, тот же алгоритм, что на
сайте). Автосохранение раз в ~15 с и при закрытии окна; журнал незаписанных операций — файлом
рядом, чтобы предложить восстановление после падения.

### 5.7. Подхват изменений

`fs_watch_start` на папку задачи: появилась новая дорожка или обновилось сырьё — тост
«обновить»; если несохранённых правок нет, подхватываем молча. Документ, изменённый снаружи
(нода дописала дорожки), приезжает тем же путём.

## 6. Структура папки — та же, что у сайта

```
{задача}/
  dialog.json          ← источник правды
  source.mp4
  01/ audio.wav  audio.peaks.json  orig.srt  es.srt
  02/ …
  exports/srt/es/01-anna.srt
```

Раскладку создаёт нода `dialogDocBuild`; если человек открыл папку без `dialog.json`, редактор
предлагает собрать документ на месте по шаблону и записать в папку. Файлы в папках дорожек —
**сырьё**, их не трогает ни редактор, ни экспорт.

## 7. Этапы

| Этап | Объём |
|---|---|
| **M1** | Окно, точки входа, модуль формата (чтение + валидация), превью, список реплик — только просмотр |

Ноды `audioPeaks` и `dialogDocBuild` — отдельная, более короткая работа; они нужны и сайту,
поэтому делать их стоит первыми.

## 8. Чего не делать

- **Не тащить сюда онлайн.** Ни `storage/*`, ни `ensureLocal`, ни синхронизации с R2: смысл
  этого редактора в том, что материал остаётся локальным.
- **Не делать плагином** (§2). Плагины — гейты обработки, окон у них нет.
- **Не переносить UI сайта.** MUI против Tailwind; переносится формат, а не компоненты.
- **Не хранить состояние интерфейса в документе** (mute / solo / высоты / масштаб) — правило
  §2.8 контракта: это состояние одного человека, в общем файле оно порождает конфликты.
- **Не читать экспортированные файлы обратно** в документ (§2.9 контракта).
- **Не переписывать документ нодой** — только дописывать (§9 контракта).
- **Не начинать в `main`** — релизная ветка с авто-сборкой (`CLAUDE.md`).
