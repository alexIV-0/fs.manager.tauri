# Runbook: настройка Telegram-ботов под клиента/проект

> Операционная инструкция «как руками настроить нового клиента» — общая для обоих плагинов:
> [autoPostTG](+TELEGRAM_AUTOPOST_PLAN.md) (постинг) и [tgCollect](TELEGRAM_GDRIVE_BOT_PLAN.md) (сбор).
> Пока всё делаем вручную на нашей стороне. Цель файла — **не забыть цепочку**, потому что
> потом её автоматизируем (см. раздел «Что чем автоматизируется»).

---

## Принципы (почему так)

- **На клиента — свои боты, отдельно для сбора и для постинга.** Два разных бота, не один.
  Причина: `getUpdates` — **один потребитель на бота** (две машины/плагина на одном токене
  начнут воровать апдейты друг у друга → `409 Conflict`), плюс авто-обнаружение каналов через
  `getUpdates` глобально для бота → шёл бы «чужой» список.
- **Имена зеркалят структуру папок.** Супергруппа = имя клиента (главная папка), тема (topic) =
  имя проекта (папка проекта). `mainFolder ↔ супергруппа`, `project ↔ тема`.
- **Создаём всё мы.** Клиент в простом случае только добавляет бот постинга в свой канал.
- **Сбор работает только в форум-супергруппе с темами** (тема несёт `thread_id` → маршрут в нужный
  проект). Для одиночного простого случая годится и обычный канал/группа без тем.

---

## Сценарий A — только постинг (у клиента свой канал)

Когда клиенту достаточно, чтобы мы публиковали в его канал.

1. **Создать бот постинга** у @BotFather: `/newbot` → имя → username (оканчивается на `bot`) →
   получить **токен**. (Или взять свободный из пула, см. ниже.)
2. **Отдать клиенту** бот (@username) с просьбой добавить его **администратором канала** с правом
   `can_post_messages`. Это единственный шаг на стороне клиента.
3. В программе: нода autoPostTG → «Add Bot» (вставить токен) → **«Найти мои каналы»**
   (`getUpdates`-обнаружение) → выбрать канал(ы). Бот должен быть добавлен в канал **до** «Найти»
   (окно апдейтов ~24 ч).
4. Готово — постинг по таймеру.

> Сбора тут нет. Если позже понадобится забирать материалы из Telegram — переходим к сценарию B.

---

## Сценарий B — сбор + постинг (наша форум-супергруппа на клиента)

Когда клиент должен **присылать** материалы через Telegram, а мы — и собирать, и постить.

1. **Создать два бота** у @BotFather (или выдать из пула): **бот сбора** и **бот постинга**.
   Сохранить оба токена.
2. **Создать форум-супергруппу** под клиента, имя = **имя клиента / главной папки**.
   - создать супергруппу (в клиенте Telegram: New Group → сделать публичной/приватной по вкусу);
   - включить **Topics** (Manage Group → Topics ON) — без этого не будет тем/`thread_id`.
3. **Добавить оба бота** в супергруппу и **выдать обоим админку**:
   - **бот сбора**: админ (или хотя бы privacy mode OFF у @BotFather) — иначе **не видит**
     медиа-сообщения; для авто-создания тем нужен `can_manage_topics`;
   - **бот постинга**: админ с правом постить/слать в темы.
4. **Создать тему (topic)** под каждый проект, имя темы = **имя проекта** (папки).
   - руками в клиенте, **или** автоматом через Bot API `createForumTopic` (бот-админ умеет —
     см. автоматизацию).
5. **Зафиксировать id в конфиге нод** (бот «прописывает» chat_id/thread_id при первом сообщении
   из темы):
   - tgCollect-нода проекта → `account` (бот сбора), `target` (супергруппа+тема) → пишет
     `chatId`/`threadId` в `options/tgSearch.json`;
   - autoPostTG-нода → бот постинга + та же тема (если постим в тему, не в отдельный канал).
6. Готово — клиент шлёт в тему проекта, бот сбора кладёт в `IN`; постинг по таймеру.

## Соглашение об именах (держать жёстко)

| Уровень программы | Уровень Telegram | id для маршрутизации |
|---|---|---|
| главная папка (клиент) | форум-супергруппа | `chat_id` |
| папка проекта | тема (topic) в супергруппе | `thread_id` |
| файл в `IN` | сообщение/медиа в теме | `message_id` |

Переименовали проект → переименовать/пересоздать тему (старую пометить неактивной, сообщения
сохранить). Это будущая автоматика (фаза 3).

---

## Что чем автоматизируется потом

| Шаг | Сейчас | Потом (чем) |
|---|---|---|
| Создать бот | вручную @BotFather | **остаётся ручным** (офиц. API нет). Обход: **пул заранее созданных ботов** → «выдать» из пула = автоматизируемо |
| Создать супергруппу + включить Topics | вручную в клиенте | **MTProto** (user-сессия): `channels.createChannel` + `toggleForum` |
| Добавить ботов в супергруппу | вручную | **MTProto** (бот сам себя добавить не может) |
| Выдать ботам админку | вручную | **MTProto** (`editAdmin`/promote) |
| Создать тему под проект | вручную / Bot API | **Bot API `createForumTopic`** (бот-админ умеет уже сейчас) — **самый ранний автоматизируемый шаг** |
| Переименовать/закрыть тему | вручную | Bot API `editForumTopic`/`closeForumTopic` |
| Записать chat_id/thread_id в ноду | вручную (или авто-discover из getUpdates) | авто-заполнение при создании темы (id возвращает `createForumTopic`) |

**Вектор автоматизации:** пул ботов (выдача) + MTProto-модуль (супергруппа, добавление и
промоут ботов) + Bot API для тем-под-проекты. Создание самих ботов — единственное, что
честно остаётся ручным; пул это маскирует.

## Готчи (из-за них чаще всего не работает)

- **Бот сбора не админ / privacy mode ON** → не видит обычные медиа-сообщения. Лечится админкой
  или `/setprivacy` → Disable у @BotFather.
- **Topics не включены** в супергруппе → нет `thread_id`, маршрутизация по проектам не работает.
- **Один бот на сбор и постинг** → конфликт `getUpdates` (409) и перемешанные апдейты. Только
  раздельные боты.
- **Две машины на одном токене бота** → тот же 409. Токен бота клиента живёт на одной машине
  (та, что синкает его папки).
- **Бот постинга не админ канала** (сценарий A) или нет прав слать в тему (B) → `403`.
- **chat_id/thread_id не зафиксированы** в ноде → сборщику некуда маршрутизировать. Прописываются
  при первом сообщении из темы или из ответа `createForumTopic`.
- **Окно `getUpdates` ~24 ч** — добавили бота и сразу жмём «Найти мои каналы»/первый поллинг.
