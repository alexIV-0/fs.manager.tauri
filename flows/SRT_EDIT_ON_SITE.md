# Флоу: папка задачи для монтажа субтитров на сайте

> **Что это.** Как собрать граф, чтобы результат обработки можно было вычитать человеком в
> кабинете сайта (`innovation-hub`, раздел «Инструменты» → редактор титров). Документ отвечает
> на один вопрос: **что граф обязан положить в папку и по каким правилам**, чтобы задача
> открылась и работала.
>
> **Статус:** 🔧 контракт зафиксирован и реализован на стороне сайта; из нод графа готовы не
> все — см. §7.
>
> **Канонические тексты (здесь не пересказываются):**

## 1. Что происходит целиком

Материал — видео с несколькими говорящими. Граф режет звук по персонажам, распознаёт речь,
переводит и складывает результат в **папку задачи**. Дальше работает человек: вычитывает текст,
правит тайминги, переносит реплики, приписанные не тому персонажу, вычитывает перевод.

Место работы человека — сайт. Значит папка задачи это **не свалка результатов, а вход чужой
программы**: её раскладку и имена читает код, который мы не правим.

```
граф (ноды)  →  OUT/<задача>/  →  синхронизатор → R2  →  каталог сайта  →  редактор титров
```

**Задача появляется на сайте не тогда, когда файл лёг на диск, а когда его увидел каталог.**
Сайт читает не бакет, а свою таблицу `project_files`, которую наполняет `notify` после заливки.
Файл, положенный в R2 мимо синхронизатора, для сайта не существует до `reindex` — это первое,
что стоит проверить, если папка на диске полная, а задача пустая.

## 2. Границы: чего сайт не делает

Список короткий, но он определяет, что обязан сделать граф:

- **не рендерит и не конвертирует** — какое видео положили, такое и играет браузер;
- **не переводит и не распознаёт** — перевод приходит готовым, в документе;
- **не переименовывает файлы** и не правит `media.video` в документе, даже когда нашёл видео
  сам: документ общий с программой, и менять его догадкой инструменту нельзя;
- **не работает с локальной папкой** — только онлайн, файлы читаются из R2 подписанными
  ссылками. Локальная работа — это наш редактор, [`DIALOG_EDITOR_PLAN.md`](../ideasAndTest/DIALOG_EDITOR_PLAN.md);
- **не чинит документ** — не прошёл валидацию, задача не открывается вовсе.

## 3. Раскладка папки задачи

Корень задач проекта — папка `OUT` (на сайте настраивается, по умолчанию `OUT`). Одна задача —
одна папка первого уровня внутри неё, имя папки человек видит как имя задачи.

```
OUT/
  Notting_Hill/                  ← задача = папка = один материал
    dialog.json                  ← ИМЯ ФИКСИРОВАНО. Нет файла — задача не откроется
    proxy.mp4                    ← видео для превью (§5); имя любое, лишь бы в корне
    master.mov                   ← мастер, если он тоже здесь: сайт возьмёт прокси
    mix.peaks.json               ← волна общего звука; путь берётся из документа
    01/                          ← папка дорожки: НОМЕР дорожки, не имя персонажа
      original.srt               ← сырьё: распознанный текст (§6)
      dialog_rus.srt             ← сырьё: перевод
      audio.wav                  ← стем персонажа, если он вообще есть
      audio.peaks.json           ←   и тогда волна к нему
    02/
      …
```

Три правила раскладки, которые не обсуждаются:

1. **`dialog.json` лежит в корне папки задачи и называется именно так.** Всё остальное сайт
   находит по путям **из** документа или подбором; сам документ — только по имени.
2. **Папка дорожки называется номером** с ведущим нулём (`01`, `02`) и совпадает с
   `tracks[].no`. Имя персонажа живёт в документе, а не в имени папки.
3. **Пути внутри документа относительны папке задачи** (`01/audio.wav`), без `..` и без
   абсолютных путей. Документ с абсолютным путём не проходит валидацию.

## 4. Что ищется по имени, а что строго по документу

Асимметрия важная, её легко нарушить:

| что | как находится | если не нашлось |
|---|---|---|
| `dialog.json` | фиксированное имя в корне задачи | задача **не открывается** |
| видео | путь из `media.video`, а **не сошёлся — любое видео в корне** папки задачи (§5) | кадра нет, титры и тайминги правятся |
| сырьё титров | путь из `origin.file` / `{NN}/{lang}.srt`, а не сошёлся — **по языку в имени** внутри папки дорожки (§6) | восстановление скажет «без сырья» |
| волны (`media.peaks`, `tracks[].peaks`) | **только точный путь из документа** | волны нет, таймлиния работает |
| стем дорожки (`tracks[].audio`) | **только точный путь из документа** | дорожку нельзя послушать в solo |

Читается так: **видео и титры прощают свободные имена, волны и стемы — нет.** Для волн и
стемов имя файла обязан правильно записать `dialogDocBuild`; для видео и титров достаточно
соблюсти правила именования ниже.

## 5. Видео: прокси и его параметры

**Кладём в корень папки задачи.** Имя любое, размер кадра любой. Порядок предпочтений
инструмента: файл со словом `proxy` или `preview` в имени → затем `.mp4` → затем остальное,
внутри группы по алфавиту. Расширения, которые считаются видео: `mp4 m4v mov webm mkv avi mxf`.

**Прокси нужен не для скорости, а для того, чтобы кадр вообще был.** Браузер играет H.264
8 бит 4:2:0 и всё. ProRes, HEVC, DNxHD, 10 бит — это чёрный прямоугольник вместо превью, при
живом и целом мастере.

```bash
ffmpeg -i master.mov \
  -map 0:v:0 -map 0:a:0? \
  -c:v libx264 -profile:v high -pix_fmt yuv420p \
  -vf "scale='min(1280,iw)':-2" \
  -crf 27 -maxrate 1500k -bufsize 3000k -preset veryfast \
  -g 25 -keyint_min 25 -sc_threshold 0 \
  -c:a aac -b:a 128k -ac 2 \
  -movflags +faststart \
  proxy.mp4
```

| параметр | почему именно так | что будет иначе |
|---|---|---|
| нет `-r`, `-ss`, `-t` | прокси обязан быть покадрово тем же материалом, что мастер | сменил 25 → 30 fps, и все титры поехали относительно картинки; человек вычитывает по неправде |
| `-pix_fmt yuv420p`, `libx264` | единственная связка, которую играют все браузеры | чёрный кадр вместо превью |
| `-movflags +faststart` | `moov` в начало файла | плеер не начнёт играть, пока не дотянет весь файл; перемотки нет |
| `-g` = частота кадров, `-sc_threshold 0` | ключевой кадр раз в секунду | прыжок на реплику декодирует полминуты видео; а прыжок на реплику — это и есть основная работа |
| `-map 0:a:0?` | звук обязателен: он же часы и «основная дорожка» превью | немой прокси = нечем проверить попадание в реплику |
| `-crf 27`, 720p | ~1–1.5 Мбит/с, ≈9 МБ на минуту | вкусовое: можно менять под материал |

Знак `?` в `-map 0:a:0?` — чтобы немой мастер не ронял прогон.

Мастер в папке оставлять можно: прокси старше по приоритету, а мастер пригодится следующим
шагам. Если мастера в папке нет вовсе — ничего не сломается.

## 6. Титры: имена файлов и язык в имени

Файлы сырья лежат **в папке дорожки**. Имена свободные, но язык обязан читаться из имени:

- **оригинал** — либо словом в имени (`original`, `orig`, `source`, `исходник`), либо кодом
  своего языка (`..._eng.srt` при `languages.original: "en"`). Единственный `.srt` в папке
  дорожки тоже считается оригиналом — перепутать его не с чем;
- **перевод** — только по названному языку: код (`ru`, `es`, `pt-BR`), трёхбуквенный (`rus`,
  `spa`), слово (`russian`, `рус`). Файл со словом «оригинал» в имени переводом не считается
  никогда, и единственный файл в папке за перевод не сойдёт.

**Язык — отдельный кусок имени**, отбитый `-`, `_`, `.` или пробелом: `dialog_rus.srt` читается,
`dialogRUS.srt` — нет. Отличить в слитном имени язык от хвоста слова нельзя, а ложное
совпадение здесь дороже пропуска: подставить в реплику чужой текст хуже, чем честно сказать
«сырья не нашлось».

Формат файлов: UTF-8 **без BOM**, обычный SRT — номер, `hh:mm:ss,mmm --> hh:mm:ss,mmm`, текст,
пустая строка.

**Зачем сырьё вообще нужно, если весь текст уже в документе.** По нему работает
восстановление: человек в любой момент может вернуть машинный результат — целиком или по
выбранным дорожкам и языкам. Реплика находит свой блок по `cues[].origin`: `file` + `index`.
Нет `origin` — реплика считается созданной человеком и не восстанавливается никогда.

## 7. Ноды: что есть и чего нет

| нода | роль в флоу | состояние |
|---|---|---|
| `transcribeVA` | распознавание речи → текст с таймингами | ✅ есть |
| `AItranslateVA` | перевод реплик | ✅ есть |
| `speech2signal` | огибающая громкости (донор кода для пиков) | ✅ есть |
| `convertFile_v2`, `createPath`, `copyFile`, `join` | раскладка файлов по папкам задачи | ✅ есть |
| `diarizeSpeakers` | разделение по персонажам → дорожки | 🎯 спроектирована, кода нет (спека: план сайта §V.3) |
| `audioPeaks` | `*.peaks.json` для волны | 🎯 спроектирована, кода нет (§V.4) |
| `dialogDocBuild` | финализатор: собирает `dialog.json` | 🎯 спроектирована, кода нет (§V.5) |
| `videoProxy` | прокси для превью (§5) | 🎯 спроектирована здесь, кода нет |

Заготовка манифеста для прокси — по образцу `audioPeaks`:

```jsonc
// plugins-dev/videoProxy/plugin.json
{
  "id": "videoProxy", "name": "Video Proxy", "version": "0.1", "apiVersion": 1,
  "type": ["nodeui", "processing"],
  "description": "Лёгкое H.264-превью рядом с мастером: для просмотра в браузере и точной перемотки.",
  "main": "videoProxy.js", "ui": "ui.json", "external": [],
  "cost": "0", "costUnit": "run", "resourcePool": "ffmpeg"
}
```

- **Вход:** `_item.import.inputFile` — видеофайл.
- **Свойства (`ui.json`):** `height` (720 по умолчанию), `crf` (27), `maxrate` (1500k),
  `gopSeconds` (1), `targetPath` (маска пути), `suffix` (`proxy`).
- **Выход:** путь созданного файла — дальше он попадает в `dialogDocBuild`, который пишет его
  в `media.video`.
- Частоту кадров и длительность **не трогает**: `-g` считается из `ffprobe` исходника.

Пока `dialogDocBuild` не написана, документ собирается прототипом — см. план сайта §V.8
(Cast Analyzer Next): та же работа снаружи конвейера.

## 8. Что обязан заполнить `dialogDocBuild`

Полный список полей — в каноническом тексте. Здесь только то, отсутствие чего ломает работу
человека, а не валидацию:

| поле | без него |
|---|---|
| `media.durationMs` | документ невалиден, задача не откроется |
| `languages.original`, `languages.targets` | нет колонок перевода; язык оригинала — `und` с предупреждением |
| `tracks[].no` | папка дорожки не находится (§3, правило 2) |
| `tracks[].name` | персонаж без имени; имя попадает в имена файлов экспорта |
| `tracks[].origin.name` | **нельзя восстановить машинное имя дорожки**: в сырье папки имён нет, это единственное место, где они есть |
| `cues[].origin.file` + `index` | восстановление реплики невозможно — она считается ручной |
| `media.peaks`, `tracks[].peaks` | нет волны (не ошибка, но работать заметно хуже) |

И три правила поведения самой ноды, они в каноническом тексте §9:

1. **дописывать, а не перезаписывать.** Повторный прогон случается после того, как человек уже
   правил реплики: перезапись уничтожит работу;
2. **`removed` уважать** — реплику, удалённую человеком, повторный прогон не воскрешает;
3. **`updatedBy: "node:dialogDocBuild"`, `revision` увеличить.** По этим полям обе стороны
   понимают, чья версия новее при слиянии.

## 9. Проверка перед сдачей задачи

```bash
# в репозитории сайта: валидация документа по контракту
node scripts/check-dialog-doc.mjs /путь/к/OUT/Notting_Hill
```

Глазами по папке:

- [ ] `dialog.json` в корне задачи, имя точное;
- [ ] в корне лежит видео, которое играет браузер (перетащить в Chrome — самый быстрый тест);
- [ ] папки дорожек названы номерами и совпадают с `tracks[].no`;
- [ ] в каждой папке дорожки есть оригинал, и язык перевода читается из имени;
- [ ] пути `media.peaks` / `tracks[].peaks` / `tracks[].audio` в документе указывают на
      существующие файлы (эти — строго по документу, подбора нет);
- [ ] папка залита через синхронизатор, а не положена в бакет руками (§1).

## 10. Диагностика: что человек видит → где чинить

Инструмент называет причину прямым текстом; таблица переводит её в место в графе.

| на сайте | причина | чинить |
|---|---|---|
| «В папке нет `dialog.json`» | документа нет или он не в корне задачи | `dialogDocBuild`, маска `targetPath` |
| «`dialog.json` не читается» / ошибка поля | документ не прошёл валидацию | `check-dialog-doc.mjs` покажет поле |
| «Видео в папке нет» | ни `media.video`, ни видеофайла в корне | `videoProxy` не отработала или положила файл в подпапку |
| «Видео `X` из документа в папке не найдено» | `media.video` указывает в пустоту, и другого видео в корне нет | путь в документе или маска пути прокси |
| «Видео `X` в папке есть, но хранилище не выдало ссылку» | **не наша сторона**: отказ подписи в R2, ключ файла не совпадает с префиксом проекта | бэкенд сайта, не граф |
| чёрный кадр вместо картинки, звука нет | контейнер играет, кодек нет | параметры §5: `libx264` + `yuv420p` |
| кадр играет, перемотка тормозит | нет `+faststart` или редкие ключевые кадры | параметры §5 |
| волны нет ни на линейке, ни на дорожках | пути пиков в документе не сошлись | `audioPeaks` + `dialogDocBuild` |
| восстановление: «без сырья» | язык не читается из имени файла или нет `origin.file`/`index` | §6 и `dialogDocBuild` |
| титры едут относительно картинки | прокси перекодирован со сменой fps или обрезкой | §5, первая строка таблицы |

## 11. Что нельзя менять в одиночку

- **формат документа** — общий с сайтом и с нашим редактором. Правка только через канонический
  текст и с обеих сторон;
- **имя `dialog.json`** и номерные имена папок дорожек — на них завязан код обеих сторон;
- **тайминги материала** — прокси, перекодировки, вставки заставок. Любая работа со временем
  после того, как документ собран, обесценивает всю ручную вычитку.

Свободны, наоборот: имена видеофайлов и файлов титров, разрешение и битрейт прокси, имя папки
задачи, состав дополнительных файлов в папке. Это и есть та часть, где флоу можно настраивать
под заказчика, ничего не согласовывая.
