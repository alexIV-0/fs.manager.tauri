# plugin.json — Манифест плагина

Каждый плагин обязан содержать файл `plugin.json` в корне своей папки. Это манифест — главный дескриптор плагина, по которому система его регистрирует, загружает и отображает.

---

## Полная структура

```json
{
	"id": "myPlugin",
	"name": "My Plugin",
	"version": "0.1.0",
	"apiVersion": 1,
	"type": ["nodeui", "processing"],
	"description": "Что делает этот плагин",
	"main": "index.js",
	"ui": "ui.json",
	"external": ["sharp", "ffmpeg-static"]
}
```

---

## Поля

### `id`

**Тип:** `string`  
**Обязательное:** да

Уникальный идентификатор плагина. Используется как ключ в системе (`id@version`). Должен быть уникальным среди всех плагинов. Рекомендуется использовать `camelCase` или `kebab-case` без пробелов.

```json
"id": "mainSearch"
"id": "copy-file"
"id": "splitFile"
```

---

### `name`

**Тип:** `string`  
**Обязательное:** да

Человекочитаемое название плагина. Отображается в интерфейсе в списке плагинов.

```json
"name": "Main Search"
"name": "Split File"
"name": "Copy File"
```

---

### `version`

**Тип:** `string` (semver)  
**Обязательное:** да

Версия плагина в формате `MAJOR.MINOR.PATCH`. Вместе с `id` формирует уникальный ключ плагина в системе: `id@version`.

```json
"version": "0.0.1"
"version": "1.2.0"
```

> ⚠️ Два плагина с одинаковым `id` но разными `version` считаются разными плагинами и могут существовать одновременно.

---

### `apiVersion`

**Тип:** `number`  
**Обязательное:** да

Версия API плагинной системы, с которой совместим плагин. На данный момент актуальное значение: `1`.

```json
"apiVersion": 1
```

---

### `type`

**Тип:** `string[]`  
**Обязательное:** да

Массив типов, определяющих роль плагина в системе. Плагин может быть нескольких типов одновременно.

| Значение       | Описание                                                                                            |
| -------------- | --------------------------------------------------------------------------------------------------- |
| `"nodeui"`     | Плагин является нодой в ReactFlow — имеет визуальный интерфейс (`ui.json`) и отображается на холсте |
| `"processing"` | Плагин участвует в процессе обработки файлов — имеет исполняемую функцию в `index.js`               |

**Примеры:**

```json
"type": ["nodeui"]
```

Только визуальная нода без логики обработки (например, Description — просто описание автоматизации).

```json
"type": ["nodeui", "processing"]
```

Нода с интерфейсом и с функцией обработки (большинство плагинов: Copy File, Split File, Convert File и т.д.).

```json
"type": ["processing"]
```

Плагин только с логикой, без отдельного UI (служебные/внутренние плагины).

---

### `description`

**Тип:** `string`  
**Обязательное:** нет (рекомендуется)

Текстовое описание того, что делает плагин. Отображается в интерфейсе рядом с плагином.

```json
"description": "Нода, которая определяет то, что мы ищем в папке IN."
```

---

### `main`

**Тип:** `string`  
**Обязательное:** да

Имя скомпилированного JS-файла с основной функцией плагина. После сборки через `build-plugin.js` это всегда файл с расширением `.js`. В исходниках (`plugins-dev`) соответствующий файл может быть `.ts`.

```json
"main": "index.js"
```

> При сборке система берёт имя из `main`, заменяет `.js` на `.ts` и ищет исходник именно с таким именем в папке плагина.

---

### `ui`

**Тип:** `string | undefined`  
**Обязательное:** нет

Имя файла с описанием UI-ноды. Если поле указано и файл существует — плагин имеет визуальный интерфейс в ReactFlow. Если поле отсутствует или пустая строка — нода не отображается на холсте.

```json
"ui": "ui.json"
```

Содержимое файла описывается подробно в документации `UI_JSON.md`.

---

### `external`

**Тип:** `string[]`  
**Обязательное:** да (может быть пустым массивом)

Список npm-пакетов, которые **не бандлятся** внутрь `index.js`, а копируются в `node_modules` рядом с плагином при сборке. Используется для тяжёлых нативных или бинарных зависимостей, которые нельзя включить в бандл (например, `ffmpeg-static`, `sharp`).

```json
"external": []
```

```json
"external": ["sharp", "canvas"]
```

> Пакеты из этого списка должны быть установлены в `node_modules` проекта во время разработки. При сборке скрипт `build-plugin.js` скопирует их папки целиком в `node_modules` внутри папки дистрибутива плагина.

Пакеты, которые подключаются через стандартный `import` и могут быть бандлованы — в этот список **не добавляются**.

---

## Жизненный цикл плагина

```
plugins-dev/
  myPlugin_0.1/
    plugin.json      ← манифест
    index.ts         ← исходник функции
    ui.json          ← описание UI-ноды
        ↓ сборка (npm run build:plugin myPlugin_0.1)
distr-plugins/
  myPlugin@0.1.0/
    plugin.json      ← скопирован как есть
    index.js         ← скомпилированный бандл
    ui.json          ← скопирован как есть
    node_modules/    ← только если есть external[]
```

После сборки плагин помещается в `distr-plugins/` и автоматически подхватывается системой при следующем запуске или перезагрузке плагинов.

---

## Пример минимального манифеста

```json
{
	"id": "myAwesomePlugin",
	"name": "My Awesome Plugin",
	"version": "0.1.0",
	"apiVersion": 1,
	"type": ["nodeui", "processing"],
	"description": "Делает что-то полезное с файлами",
	"main": "index.js",
	"ui": "ui.json",
	"external": []
}
```

---

## Пример без UI (только обработка)

```json
{
	"id": "helperUtils",
	"name": "Helper Utils",
	"version": "0.0.1",
	"apiVersion": 1,
	"type": ["processing"],
	"description": "Вспомогательные утилиты без интерфейса",
	"main": "index.js",
	"external": []
}
```
