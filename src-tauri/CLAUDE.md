# src-tauri — Rust-бэкенд

## Новая команда = ДВА места + регенерация

Список команд в `lib.rs` **ровно один** — он же даёт типы, он же регистрирует рантайм:

1. Реализация: `#[tauri::command] #[specta::specta]` в `src/commands/<модуль>.rs`, модуль объявлен в `src/commands/mod.rs`. Свои структуры в аргументах и возврате — с `#[derive(specta::Type)]`, иначе `collect_commands!` не соберётся.
2. `collect_commands![…]` в `specta_builder()` (`lib.rs:53`).
3. Регенерация биндингов: `cargo test export_bindings` → перепишет `../src/bindings.ts` (headless, без GUI; в debug-сборке то же делает `run()`).

**Так было не всегда.** До 2026-08-11 списков было ДВА: `collect_commands!` для типов и `tauri::generate_handler!` для рантайма, — и компилятор их расхождение не ловил. Забыть второй = команда компилируется, типизируется, сборка зелёная, тесты зелёные, а фронт получает «command not found». Так однажды умер весь клиент хранилища целиком, 26 команд. Теперь рантайм берётся из того же списка (`.invoke_handler(specta.invoke_handler())`, `lib.rs:511`), и забыть стало нечего.

Два стража остались, но сторожат другое (`cargo test --manifest-path src-tauri/Cargo.toml`):

- `список_команд_ровно_один` (`lib.rs:551`) — что `generate_handler!` не вернулся рядом. Вернуть его ничто не мешает, а это молча вернёт и всю проблему.
- `сырые_invoke_из_ts_существуют_в_рантайме` (`lib.rs:592`) — что каждая команда, которую TS или плагин зовёт **строкой** (`tauriAPI.invoke('http_fetch')`), в списке есть. Этот путь типы обходит по определению: переименуешь команду в Rust — компилятор и `tsc` промолчат, сломается в рантайме.

Исключение по дизайну: path-утилиты фронт считает чистым TS (`lib.rs:125`) — в specta они есть (их зовут плагины), но обёртки в `src/Utils/` работают локально.

## Экспорт биндингов

`export_specta_bindings()` обязан идти с `.bigint(BigIntExportBehavior::Number)` — по умолчанию specta-typescript падает на `u64`/`i64`. Не убирать.

`src/bindings.ts` — артефакт: правки в нём затираются следующим `cargo test export_bindings`. Camel-имя на фронте (`commands.storagePathInfo`) генерится из snake-имени команды (`storage_path_info`).

## Права окон (capabilities)

Два файла в `capabilities/`, и это разделение смысловое:

- `default.json` — `"windows": ["*"]`, то есть все четыре окна: события, пути, управление собственным окном, **текстовый** буфер обмена.
- `main.json` — `"windows": ["main"]`, только главное окно: `process`, `updater`, `drag`, буфер обмена для **файлов**. Каждое подтверждено единственным местом вызова (`AppUpdaterAccordion`, `fileSystemActions`, `dragOut`) — окна логов, нод и превью их не получают.

Правила:

- **Наши `#[tauri::command]` через capabilities НЕ проходят** — они не гейтятся вообще. Здесь описаны только официальные плагины и `core:`. Не искать в этих файлах ограничений на свои команды: их там нет.
- Файлы **проверяются на сборке**: неизвестное разрешение = `cargo check` падает с перечислением допустимых. То есть опечатку компилятор поймает, а вот **лишнее** право — нет.
- Добавляешь плагин Tauri в JS — сначала реши, каким окнам он нужен, и класть в `main.json`, если не всем.
- Открытый вопрос: `fs:*` в `default.json` — из JS плагин `@tauri-apps/plugin-fs` **не импортируется нигде**, то есть права выглядят мёртвыми. Но `assetProtocol` включён со скоупом `**`, а `toFileUrl`/`convertFileSrc` используются широко, и связь скоупа asset-протокола с `fs:scope` по коду не проверяется — ломается только в рантайме. Убирать эти семь строк можно **только** прогнав приложение: превью картинки, превью видео, загрузка плагина.

## Соглашения

- Команды группируются по модулям в `src/commands/` (`fs_commands`, `storage_commands`, `ffmpeg_commands`, `ae_commands`, …). Новая тема — новый модуль, а не свалка в существующий.
- `src/storage/` — клиент удалённого хранилища (R2 через бэкенд-API), самая покрытая тестами зона: `client`/`sync`/`upload`/`index`/`evict`/`state`. Правки там сопровождать тестами — здесь это норма проекта, а не пожелание.
- События наружу эмитить broadcast'ом (без target), если событие нужно нескольким окнам: фронт слушает window-scoped (см. `src/Utils/tauri-api.ts`), и `emit_to` в чужое окно до слушателя не дойдёт.
- `apply_vars` в `src/commands/db_analytics.rs:131` — **ручной дубль** масок из `src/Utils/masks.ts`. Меняешь маски там — правь и здесь.
